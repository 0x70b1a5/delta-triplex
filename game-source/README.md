# Delta Triplex

A rotating triangular nonogram with a shared C rules engine, an SVG board and DOM controls. The standalone HTML embeds its Emscripten WebAssembly engine and has no runtime network dependencies. The Site wrapper serves `public/game.html`.

## Homepage

The homepage is a four-row triangle: the top seven-cell strip is a filled DELTA TRIPLEX banner, the five downward-facing middle cells offer Today’s Puzzle, How to Play, Endless, Past Puzzles and Load. The upward cell directly above the credit opens Create; upward cells use 25% of the empty-cell color over the background (half the intensity of crossed cells), and the credit tip links to https://lovecrypt.itch.io/. On desktop, half the credit tip extends below the viewport. Mobile keeps the triangle equilateral and centered, allowing slight side bleed.

The title and triangle menus use bundled Michroma in uppercase (SIL Open Font License; see `fonts/OFL-Michroma.txt`). The build embeds the font and its license, preserving standalone/offline deployment. Oxanium and Space Grotesk remain alternative title options.

Endless Mode uses the same triangular layout, adding complete rows for additional options. Past Puzzles is a seven-row submenu triangle like the others: the banner holds the title and month picker, and the days fill the five middle rows left to right from the top-left corner, alternating downward and upward cells (11 + 9 + 7 + 5 + 3 = 35, enough for any month). Cells past the month's last day are dim. The menu backdrop keeps the main menu's lattice size in every submenu. A native month/year picker ranges from September 2026 through the current local month, and future dates are disabled. Dates with a released daily puzzle open it; solved days show a check, started days a dot, and released days without a puzzle are dimmed. Today’s Puzzle plays today's daily directly, falling back to the calendar with a message when it is unreleased or the server is unreachable. How to Play starts the three tutorial puzzles; finishing or skipping returns home. Each submenu has a Back button in its bottom tip. Opening a submenu zooms the entire homepage toward the selected cell over 360ms: neighboring cells move offscreen while the full submenu is drawn immediately inside the expanding cell. Both menus stay opaque throughout, with a triangular background behind the submenu covering the old button label. Back reverses that whole-menu camera movement. Both menus are inert during the transition, and resize or reduced-motion changes settle it cleanly.

All triangle menus flash outward from the bottom cell in shared-edge distance waves, advancing every 500ms through upward fillers and downward cells to the banner. Corner contact alone does not advance the wave. Labels retain contrasting colours throughout each pulse.

Appearance offers System (the default), Light, Dark and Colorful, persisted under `delta-triplex-theme`. System follows OS changes; Light uses white backgrounds and black filled cells, and Dark reverses them. Colorful restores random contrasting puzzle palettes and a gently drifting menu palette. Background and filled-cell picks override any theme independently; clear restores that theme's automatic colour, and the dice chooses a contrasting colour. Picks persist across themes and reloads under the original `delta-triplex-rotation-colours` key. The menu's drift respects picks and never changes the gameplay palette.

Palette generation, override composition, contrast and flash mixing live in `palette.js`; the UI owns only preference persistence and applying the resolved palette. System/Light/Dark use ROYGBIV flash stages, including with custom colours. Colorful uses the original white pulses. All modes retain the same shared-edge propagation. Idle rainbow waves continue their colour sequence across loops. Motion pauses while hidden and respects reduced motion. Hovered, pressed and keyboard-focused buttons use the filled-cell colour with contrasting text.

On the first game start (including a shared puzzle link), a native modal offers Light, Dark, System and Colorful with lightweight SVG triangle previews. The current theme is preselected and choices preview immediately through the existing theme controls. Start playing or Escape accepts the choice; `delta-triplex-theme-welcome` prevents repeat prompts. The board and game clock pause while it is open. Browser Back closes the chooser before leaving the game.

## Playing

Tap/click a triangle to cycle empty → filled → crossed → empty. Right-click crosses or clears. Crossed cells have half the background opacity of unmarked cells; their cross glyph remains fully opaque and contrasts with the composited background. Every strip must match its run-length clues; crosses are optional. Two clue sides are visible at a time, with no selected-row highlighting. Read each clue sequence from outside toward the board.

The menu's Solving section has an opt-in **Auto-cross solved lines** switch (off by default, remembered under `delta-triplex-auto-cross`, hidden while editing). When a stroke ends, every line whose filled runs match its clue has its remaining unknown cells crossed, and one undo reverts the stroke with its crosses; switching it on crosses already-met lines (including `0` clues) as a single undoable step. Only the two clue sides on screen count, so a hidden clue never decides whether a cell is crossed or uncrossed: the view reports its visible axes to the engine (`game_visible_axes`) once a turn settles, newly shown sides that are met are crossed as one undoable step, and crosses held by a side that turns out of view stay until it is shown again. Matching is by run pattern only, so a clue met in the wrong cells spreads the mistake. Tutorials, the editor and solved boards are never auto-crossed. Puzzle Settings (name, size, export) appear in the menu only while editing.

Desktop layouts (900px and wider) center a maximized point-down triangle with a horizontal top base. Mobile layouts point right: the same view turned 30°, so the corner pointing up-right on desktop points right on a phone. Turning reveals the hidden clues in 120° steps. Use the rotation icons, arrow keys, wheel, a swipe (45px desktop / 90px mobile), or a two-finger twist. Mobile swipe preview sensitivity is half desktop sensitivity. On a phone a swipe turns the board like a wheel about its pivot, judged from where the drag starts: rightward above the pivot or downward right of it turns clockwise, and the opposite halves reverse. Desktop swipes keep right/down as clockwise. A gesture cancels without painting; incomplete gestures ease back without counting a turn. Buttons and cell input pause during animated settling. Scroll events are discarded during a turn and for another 420ms after a scroll-triggered turn finishes, so lingering wheel momentum cannot accumulate a duplicate. Reduced motion uses the same cooldown after its instant turn.

Each ordinary turn eases over about 420ms. The board rotates about its fixed centroid. Both layouts maximize and center the combined triangle and hints across all three resting orientations. The pivot stays fixed, and the board shrinks only as needed during a turn. Fitting is cached until viewport or clue geometry changes. Background and fill hues follow the same angle, including gesture previews and snap-back: each 120° turn shifts hue by 120°, and three turns return to the selected palette. Saved color selections remain the base palette; neutral colors remain neutral. Hint text uses the filled-cell color. On a portrait phone, puzzles of every difficulty draw each visible rank as a vertical column above or below its edge, so the grid can use the full width and the cells stay large enough to tap. Desktop draws the same columns turned a quarter clockwise: each rank is a horizontal row to the left or right of the point-down triangle, with identical spacing, rails, joints and fades, and upright numerals. Everything said of columns below applies to desktop rows in that turned frame (above → right, below → left). Phone boards keep an 8px screen margin so the triangle uses the side gutter; desktop keeps 24px. A column hangs from the outer of its two bordering corners — the higher corner above the triangle, the lower corner below — rather than from the triangle's top or bottom extreme. Numerals in a column are spaced three times further apart than before, and each numeral is drawn 50% larger than that pitch. Neighboring columns share one side line, so only the outer ends of the row keep a line of their own. The lines are the filled-cell color and fade out at the end farthest from the board. The fade runs for 1.24 pitch-heights, twice the former length, so it begins closer to the triangle. When two adjacent columns have both settled so their numerals are dim, the line between them is drawn at that same 25% opacity. A line beside an unsolved column, including each outer end of the row, stays at full strength. Each line meets its grid vertex along the rank direction, 60° from vertical: either a circular turn whose radius is 80% of a cell, or a single 120° corner. The turn shifts the numerals to the right of the vertex they label. Appearance offers Clue lines → Corner (the default) or Curve, for phone columns and desktop rows alike, remembered on this browser. A short or wide mobile viewport keeps the diagonal clues when that makes the cells larger. Numbers disappear during turns.

## Completion and effects

The solved notice, Share, Next, Undo, Reset and Menu share one bottom row. Desktop shows the time and rotation count beside Solved; mobile omits the Solved label and names the button Share solution. Solved boards reclaim the clue space: mobile uses equal left/right margins, while desktop uses equal top/bottom screen margins. The triangle keeps its proportions and fits the available space. Next reads “Next →” and cycles through contrasting hues while visible; reduced motion uses a static accent. Share retains the full result regardless of viewport size, using the native share sheet, clipboard, or a selectable-text fallback.

Filling a cell triggers the C engine's edge-adjacent ripple, rendered through per-cell light values and rainbow stages in SVG. That wave continues past each visible strip's outer cell into its numerals — nearest the board, then the next, then the outermost — one 55ms hop each, with the same pulse. Light and Dark paint those numerals the following rainbow stage. Colorful pushes them toward white, harder than a cell, because the glyph is already near the top of the ramp. When a row first matches, its numerals flash one by one from the outside toward the board, then that clue stays at 25% opacity until the row no longer matches. A single run dims the same way, with one pulse, once the marks pin it: every placement of the clue consistent with the filled and crossed cells puts that run in the same place, and those cells are all filled (for example, `1 1 4` with four filled cells at the end and the fifth crossed). A run pinned before its row matches stays dim through the row's flash. Lines the marks contradict pin nothing, and only whole-row matches dim the rails. The pulse holds full opacity on the way up and eases the composited color into the dim glyph on the way down. Rows that were already matched when the puzzle opened are dim immediately. A later flash on a numeral that is already dim eases that same composited color from the dim glyph to the flash color and back along one smooth curve, so it does not step to full brightness. Reduced motion skips the flash. Taps commit on release to distinguish them from rotation gestures; the effect clock starts at that commit rather than waiting for the next animation frame. Solving returns the board to the puzzle's orientation with the original 500ms cubic-ease-out spin: 360° when the board is already facing that way, otherwise 480° in whichever direction reaches it, so the spin is never less than a full turn. The palette hue follows that extra turn back to the chosen colors. Reduced motion sets the orientation immediately. The spin keeps the smoothstep 1 → 1.1 → 1 scale pulse; the board rotates about the same central active cell as the original raylib camera, without edge anchoring or fit constraints. Shared-edge waves then continue flashing every 500ms from the visible point to the base, with one distance shell visibly active until the next takes over. The wave starts at the visible point in either layout. Victory effects never increment rotations or change the frozen solve result. All animation and flashes respect reduced motion. The old selected-strip idle shine is not used because this design has no selected strip.

The stopwatch counts active puzzle time, pausing in menus and hidden tabs. Built-in progress, elapsed time, rotations and view persist together. Reset begins a new attempt; undo does not erase rotations. Custom imports and editor trials start fresh, matching their empty boards. An Endless attempt is the exception: its number is written to the address bar as `#endless=hard-12`, and every numbered puzzle's board, stopwatch, rotations, view and first solve are stored on this browser under `tri-endless-v2`. Reloading that address resumes the same puzzle. Leaving it removes the address so a later reload stays on the menu. A solved daily or Endless puzzle always reopens showing its solution and the solve that counted, even after a reset and a partial replay; Reset starts another replay. Saved solved boards without a timing record show a previous-session result instead of inventing a time.

## Daily puzzles

Dailies are curated, not generated: `server/dailies/*.txt` holds the designs, and `server/api.mjs` releases each one on its date (see [server/README.md](../server/README.md)). `daily.js` fetches the puzzle, plays it as a named custom board at `#daily=YYYY-MM-DD`, and keeps progress, timing and the first solve in `tri-daily-v1`. Replays after a reset never replace the first solve. The first solve is submitted with the board, time and rotations; a Stats button in the completion row opens the results a moment after the reveal: the solver count, time and rotation standings (top X%), rotation par (the median), and a histogram of each with the player's bin highlighted and the median time marked as a labelled line. Endless adds a second set over every solve of that difficulty, headed with its solve count. Shares name the puzzle and include those standings. Results that cannot be sent are retried on later visits.

There are no accounts. Settings → Stats sync shows the player's random code and accepts one from another device; it carries daily and Endless solves.

## Endless

Endless puzzles are numbered per difficulty and are the same for every player: Hard #12 is one fixed board, generated in the browser by `game_endless(difficulty, number)`. Sprout (414 boards) and Easy (52,532) shuffle every board the generator can accept, so they never repeat and eventually run out; Medium, Hard and Impossible derive a seed from the number and are unbounded. Changing that derivation in `src/generator.c` renumbers every puzzle and orphans recorded solves.

Picking a difficulty reopens the number last played there, or the next unsolved one after it; Next goes to the lowest unsolved number after the current one. Each difficulty button shows how many of its puzzles are solved, and the Solves cell (the upward cell above Back) lists solved counts by difficulty, leaving out difficulties with none. The first solve of each number is submitted like a daily's. Its Stats button (not opened automatically, so Next stays one tap away) ranks the solve among everyone who played that number and, because few people share any one puzzle, among every solve of that difficulty. Share links use `#endless=hard-12`; Load also accepts `Hard 12`, `hard #12` or `hard12`.

A returning player (any daily progress on this browser) who has not solved today's released puzzle sees a spark run around the Today's Puzzle cell, cycling through the spectrum with a fading trail. Reduced motion draws a still rainbow outline instead.

## Puzzles and sharing

The stock level selector is retired. The old engine fixtures and `#level=` links remain available for compatibility with previously shared puzzles; the menu no longer starts or advances stock runs. Endless difficulties Sprout, Easy, Medium, Hard and Impossible use side lengths 3, 4, 6, 8 and 10. Difficulty IDs are Easy 0, Medium 1, Hard 2, Impossible 3 and Sprout 4. The C generator certifies uniqueness through line-placement deduction and enforces the difficulty's minimum deduction rounds. Next advances the tutorial or opens the next unsolved Endless number; imported puzzle completion returns home, and editor trials return to authoring.

Every puzzle has an `orientation`: 0, 1 or 2 clockwise 120° turns from the canonical base-up view. A puzzle opens facing its orientation and its solve always ends there; the hue shift that follows turning is measured from it. Authors set it by turning the board while editing (those turns are not counted), and Try opens it the way players will see it. Create, the menu's Level editor and the editor's New button (beside Try, while editing) open a New puzzle dialog asking for a name and size; outside the editor it also offers to continue the saved draft, and it notes when creating will replace that draft. While editing, a warning beside Try appears once painting pauses if the drawn board is not line-solvable: `! Unsolvable` when another board fits the same clues, `! Needs guessing` when the answer is unique but needs trial and error, or `! Unverified` when the check runs out of budget. It opens a dialog explaining the problem. `game_solubility` runs `puzzle_solubility`: line deduction first, then a budgeted search that counts up to two solutions. Built-in levels, tutorials and generated puzzles use 0, so seed codes are unchanged. JSON uses `format: "tri-logic"`, `version: 2`, `cellOrder: "north-row-major"`, `size`, `name`, `orientation`, and a binary `solution` of length `size²`. Canonical index is `r*r + 2*i + o`, where `r = i+j+o`. JSON uses `version: 3`; a missing orientation imports as 0. Packed links use version 3: a version byte, a byte holding the size (low four bits) and orientation (next two bits), then MSB-first solution bits, so orientation adds no length. Generated puzzle codes pack the 32-bit unsigned seed and 3 difficulty bits into seven Crockford Base32 characters grouped `XXX-XXXX` (`difficulty * 2^32 + seed`). That one code is sufficient to reproduce a generated puzzle with the current generator. Seed codes open one-off puzzles outside the numbered Endless sequence. The code beside the timer is clickable to copy; Load accepts the code, an Endless number, or a full puzzle link, and also offers JSON import. Input is case-insensitive, ignores spaces/hyphens, and accepts O as 0 and I/L as 1. The tooltip shows the raw hexadecimal and decimal seed plus difficulty. Unseeded imports and tutorials omit the code. Share links use `#seed=XXX-XXXX` for seeded puzzles and `#endless=` for numbered ones. Separate hexadecimal seed/difficulty parameters and version-1 and version-2 packed links are no longer supported. Pre-release formats may change; backward compatibility is not a requirement.

The share origin is `https://deltatriplex.com/`. A shared link opens straight into play. Visitors do not get Edit, which would paint the solution. How to Play sits at the bottom left and cycles hues the same way Next does, until the first mark or turn; reduced motion keeps one static accent. Closing that lesson returns to the shared puzzle. Playable HTML exports embed the puzzle in the same application and can be re-exported. Editor drafts and built-in attempts are separate; the rotating design uses `tri-rotate-*` progress/draft/timing storage keys and its own theme preference key.

## Source map

- `src/puzzle.c`: strips, run matching, cell state and completion.
- `src/generator.c`: generation and deduction certification.
- `src/main.c`: engine API, saves/undo, effects, canonical-cell snapshots, and legacy raylib geometry.
- `daily.js`: daily puzzles, daily and Endless first-solve submission, stats popover, sync code and the Today's Puzzle spark.
- `rotate.js`: current SVG renderer, fit/anchor calculations, gestures, timing, completion UI and brag sharing.
- `app.js`, `editor.js`, `flow.js`, `share.js`, `back.js`: browser bridge, palettes, editor/import/export, navigation/generation, link formats and history.
- `shell.html`: document structure and responsive layout.

## Build and checks

Requires Emscripten 4.0.16, raylib 5.5, Python 3, Make and Node. With Emscripten activated and raylib available:

```sh
make -C /path/to/raylib/src PLATFORM=PLATFORM_WEB
make -C game-source web RAYLIB=/path/to/raylib
cp game-source/web/index.html public/game.html
npm --prefix game-source install
npm --prefix game-source test
make -C game-source test test-generator
make -C game-source test-game RAYLIB=/path/to/raylib
```

The tests run real compiled WebAssembly with a DOM harness and stub only graphics initialization. They cover input/undo, mobile swipe sensitivity, animated rotation and viewport fit, clue anchors, all five Endless difficulties, persistence, timing, sharing/export round trips, footer structure/icons, SVG flashes, victory timing and reduced motion. Native tests cover clue rules, geometry, effects, custom/editor history and uniqueness certification. Geometry tests support macOS and GNU linkers.

The legacy native raylib desktop target remains an engine/debug view; the current rotating interface is the browser/SVG application. `test_shared.cjs` forwards to the maintained rotation integration suite.
